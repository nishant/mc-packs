# mc-packs

Minecraft Bedrock packs for a Realm. Each folder in `packs/` is a self-contained pack: behavior packs `*_bp` (`manifest.json`, `scripts/main.js`, `scripts/config.js`) and one resource pack, `rain_rp`, whose files are generated by `tools/gen-rain/` (`npm run gen:rain`; never hand-edit its textures, fogs, sounds or sound definitions).

## Rules

- **Docs stay current.** Any change to a pack's behavior, commands, config options or saved data must update `docs/PACKS.md` (and the pack table in `README.md` if the summary or commands change) **in the same commit**. `npm run check` fails if a pack, a registered command or a `config.js` option is missing from the docs. That only checks coverage, so make sure descriptions and defaults are still accurate too. The in-game `/realm:help` text (`packs/help_bp/scripts/catalog.js`) is generated from each pack's summary, `### How to use` and Commands table: after changing those, run `node tools/help-catalog.mjs` (it bumps `help_bp`'s patch version); `npm run check` fails until you do. Write Commands rows for players: give the default, with the option name in parentheses (`default 64, \`defaultRadius\``).
- **The docs are also the players' docs.** `docs/PACKS.md` is published on https://mc.nish.software/realm/ (generated by `minecraft/tools/pack-docs.mjs` in `nishant/hosting`; see "Publishing to mc.nish.software" in PACKS.md). Every pack section needs a `### How to use` (numbered steps, operators last; `npm run check` enforces it). Write in plain American English (color, gray, behavior, traveled), but quote in-game text and ids exactly as the code has them, in backticks. After a change players should see, regenerate the realm page in the hosting repo in the same piece of work.
- **New pack:** add `packs/<folder>/` (its `main.js` must answer `/realm:help`: copy the `realm:help_ping` responder from the end of any other pack, with its own folder name; `npm run check` enforces it), a `## <Name> — \`<folder>\`` section in `docs/PACKS.md` (same layout as the others: what players see, Commands, Configuration, Saved data), a row in the README table, and a mention in "How the packs work together" if it interacts with other packs.
- **Game text is plain ASCII** (plus `§` codes): Bedrock draws a line with `…`, `–`, `•`, `·` or an emoji in a smaller fallback font. Settings are named for what they do with an Enabled/Disabled switch (`invert` for options stored as `off`); never "Turn off ...". `npm run check` enforces the ASCII part.
- **Stable APIs only:** `@minecraft/server` 2.1.0 / `@minecraft/server-ui` 2.0.0, no beta modules or experiments, because the packs run on a Realm.
- **Packs stay independent:** no imports between packs. Coordinate through tags, scoreboards or script events, like the AFK pack's `afk` tag that the Stats pack reads, or the `realm:help_ping`/`realm:help_pong` script events `/realm:help` uses to see which packs are installed. Dynamic property keys use the pack's own prefix (`news:…`, `stats:…`).
- **Commands all use the `realm:` namespace**, named `realm:<pack>` or `realm:<pack>_<action>` (e.g. `realm:news_edit`). Bedrock allows only one command namespace per add-on, and a bundle is one add-on: a second namespace throws `NamespaceMismatch` and those commands never register. `npm run check` and `npm run bundle` fail on any other namespace.
- **Bundle or standalone:** `npm run bundle -- --all` (the Realm Bundle) takes every behavior pack except those in `tools/standalone.json` (`rain_bp`); resource packs are never bundled. Standalone and resource packs still follow every rule here (docs section, `realm:` namespace, the `/realm:help` responder for behavior packs) so they can join the bundle later; `tools/help-catalog.mjs` leaves resource packs out of the help, since they can't answer it.
- **Pictures and sound clips** go in `docs/media/` and in a pack's `### See and hear it` subsection (`![caption](media/…)`, `[label](media/….mp3)`); the realm page shows them as a gallery. The rain packs' are generated (`node tools/gen-rain/renders.mjs`, `node tools/gen-rain/sounds.mjs --audition docs/media/rain`): rerun them when the rain texture, fogs or sounds change. Label renders as renders, never as screenshots.
- **Version bumps:** increase `header.version` in a pack's `manifest.json` whenever its contents change.

## Commands

```bash
npm run check     # tsc, ASCII game text, docs, commands, help catalog, rain_rp textures/fogs. Run before every commit
npm run build     # dist/<folder>.mcpack
npm run bundle    # merge packs (see the bundle-packs skill)
npm run gen:rain  # regenerate rain_rp (sounds need ffmpeg with libvorbis)
```
