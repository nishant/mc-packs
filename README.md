# mc-packs

Minecraft Bedrock add-ons for my Realm. Each folder in `packs/` is a self-contained pack: behavior packs (`*_bp`) and seven resource packs (`rain_rp`, `sky_rp`, `translucent_rp`, `hud_rp`, `platypus_rp`, `build_rp`, `silly_rp`). They all use only the stable Script API (Minecraft **1.21.100+**), so no experimental toggles are needed. Two packs override a vanilla entity file (Translucent Tools Switch: the player; Dolphin Friends: the dolphin); those copies are refreshed from the newest vanilla files when Mojang changes them. Every behavior pack ships in the **Realm Bundle** and every resource pack in **Realm Resources**, so the realm needs only two packs; each is also downloadable on its own.

📖 **Full documentation (what each pack does, how to use it, every command and config option): [`docs/PACKS.md`](docs/PACKS.md).** Players read the same text on **[mc.nish.software/realm](https://mc.nish.software/realm/)**, which is generated from it.

**Running these packs on your own Realm or server?** [`docs/SERVER_SETUP.md`](docs/SERVER_SETUP.md) covers requirements, installing on a Realm or a dedicated server, operator setup, server size, performance and removing a pack cleanly.

## Quick start

```bash
npm install
npm run build                 # dist/<folder>.mcpack for every pack
npm run bundle -- --all       # or: every behavior pack in one dist/realm_bundle.mcpack
npm run bundle -- --resources # and every resource pack in one dist/realm_resources.mcpack
```

Open the `.mcpack` on a device with Minecraft, then go to **Realms → ✏️ Edit Realm → Behavior Packs** and activate it (**Resource Packs** for `realm_resources` or a single resource pack, at the top of the list). Use the individual packs **or** a bundle, never both. See [Installing](docs/PACKS.md#installing-on-a-realm) and [Bundling](docs/PACKS.md#bundling-packs-into-one).

With Claude, `/bundle-packs` asks which packs to include (**All packs** is the first option) and builds the bundle.

```bash
npm run check     # type-check against @minecraft/server 2.1.0 / server-ui 2.0.0; ASCII game text, docs/PACKS.md complete, realm: commands, stories, game ids, script events, action bar requests, unit tests, settings.js / zones.js / side.js / diag.js / name-labels.js copies, help and admin catalogs, news, generated resource packs, version bumps (last)
npm run test      # the unit tests alone (tools/**/*.test.mjs, about 1 s)
npm run gen:rain  # regenerate Realistic Rain's textures, fogs and sounds (sounds need ffmpeg)
npm run gen:sky   # regenerate Realm Skies
npm run gen:translucent  # regenerate Translucent Tools
npm run gen:glyphs  # regenerate the Minimap's icon font (hud_rp) and packs/map_bp/scripts/glyphs.js
npm run build     # one .mcpack per pack
npm run bundle    # merge packs into one (--list [--json], --all, --resources, --packs a,b, --name, --title, --icon)
```

| Path | |
|---|---|
| `packs/<folder>/` | One behavior pack: `manifest.json`, `scripts/main.js`, `scripts/config.js`, and `scripts/settings.js` (what Realm Settings can change in it). `rain_rp` is a resource pack whose textures, fogs, client biomes, sounds and sound definitions are generated by `tools/gen-rain/` (its particle files and manifest are hand-written); `sky_rp` (particles, fogs, textures) is generated whole by `tools/gen-sky/`, manifest and icon included, so its version is bumped in `gen.mjs`; `translucent_rp` is a resource pack (attachables, textures), generated by `tools/gen-translucent/`; `hud_rp` is a hand-written resource pack (one JSON UI file) |
| `docs/PACKS.md` | Documentation, also published on mc.nish.software/realm. **Update it in the same commit as any pack change**; `npm run check` enforces it |
| `tools/build.mjs`, `tools/bundle.mjs` | Packaging, with no dependencies |
| `tools/lib/` | Shared by the tools: `zip.mjs` (file listing and the `.mcpack` zip writer) and `commands.mjs` (the `realm:` namespace and the commands a pack registers) |
| `tools/standalone.json` | Packs that `bundle --all` / `--resources` leave out, to run next to the bundles (none today) |
| `tools/gen-rain/` | Generates `rain_rp` from Mojang's vanilla files in `tools/gen-rain/vanilla/` and the realm owner's rain and thunder recordings (`recordings.json`; the originals go in the git-ignored `tools/gen-rain/sources/`) (`npm run gen:rain`); `npm run check` fails if its textures, fogs, client biomes or sounds are stale (`sounds-lock.json` lets the sounds check run without ffmpeg). `renders.mjs` and `sounds.mjs --audition docs/media/rain` make the rain packs' pictures and sound clips; `png.mjs` is the PNG reader and writer the generators share |
| `tools/gen-sky/` | Generates `sky_rp` (Realm Skies: the particles and fogs of the weather, sky and trail packs) from code, no source files (`npm run gen:sky`); `npm run check` fails if `sky_rp` is stale |
| `tools/gen-translucent/` | Generates `translucent_rp` from Mojang's vanilla files in `tools/gen-translucent/vanilla/` (`npm run gen:translucent`); `npm run check` fails if any of its files are stale |
| `tools/gen-glyphs/` | Generates the Minimap's icon font `hud_rp/font/glyph_F3.png`, the names of its characters `packs/map_bp/scripts/glyphs.js` and the render `docs/media/map/map-hud.png` from code (`npm run gen:glyphs`); `npm run check` fails if any is stale |
| `docs/media/` | Pictures and sound clips shown in `docs/PACKS.md` (`### See and hear it`) and on the realm page |
| `tools/check-docs.mjs` | Fails if a pack, its `### How to use`, a command or a config option is missing from the docs |
| `tools/check-commands.mjs` | Fails if a command or enum isn't in the `realm:` namespace, or two share a name |
| `tools/check-pipeline.mjs` | Fails if a check tool, a tool with `--check` or the unit tests aren't in `npm run check`, or a test scenario's header runs another file |
| `tools/check-ids.mjs`, `tools/check-ids.allow.json` | Fails on a `minecraft:` id that isn't a Bedrock id (`@minecraft/vanilla-data`), or an id in a typed place (`spawnEntity`, `setType`, `typeId ===`, commands...) that is neither vanilla nor one of our packs'; `--list` ignores the allow list |
| `tools/check-events.mjs`, `tools/check-events.allow.json` | Fails on a script event outside `realm:`, or a list or player-text payload that isn't split or capped under 2048 characters; `--list` ignores the allow list |
| `tools/check-actionbar.mjs`, `tools/check-actionbar.allow.json` | Fails on a `setActionBar` with no `realm:actionbar` request before it (the action bar protocol); `--list` ignores the allow list |
| `tools/check-versions.mjs` | Last in `npm run check`: fails when a pack's files changed since `origin/master` without a higher `header.version` |
| `tools/**/*.test.mjs` | Unit tests (`npm run test`, part of `npm run check`) |
| `tools/side-shared.js`, `tools/sync-side.mjs`, `tools/name-labels-shared.js`, `tools/sync-labels.mjs` | The side boxes code (each side box pack's `scripts/side.js`) and the name label code (`scripts/name-labels.js` of Townsfolk, Merchant Caravan, Wanderers and Story Questlines); the sync tools refresh the copies, `--check` (part of `npm run check`) fails on a stale one |
| `tools/diag-shared.js`, `tools/sync-diag.mjs` | The diagnostics protocol (`realm:diag_ping` / `realm:diag_forget`, used by `/realm:diag`): every behavior pack's `scripts/diag.js` is a copy with its folder, name and version filled in, imported first by its `scripts/main.js`. Run `node tools/sync-diag.mjs` after **every version bump** (the copy carries the version) and after changing the shared file; it also adds the copy and the import to a new pack. `--check` (part of `npm run check`) fails on a stale copy or a missing import |
| `tools/test-bds/suite.mjs` | Runs every scenario in `tools/test-bds/examples/` with the command in its own header and prints a pass/fail table (`--jobs 2 --retry`, `--filter <regex>`, `--json <out>`); `--perf 10,40 [--perf-seconds 120] [--perf-only a_bp,b_bp]` runs the perf soak once per player count with the profiler and compares each pack with the budget |
| `tools/test-bds/lib/profile.js` (`run.mjs --profile`) | The profiler: times every pack's callbacks during a scenario and reports ms per tick, the costliest callbacks and server TPS (`--profile-json <file>` for the JSON report) |
| `tools/check-ascii.mjs` | Fails if a pack's script code (comments aside) or English lang file holds a character other than ASCII and `§`; the Minimap's private-use glyphs are allowed only in `packs/map_bp/scripts/glyphs.js` |
| `tools/settings-shared.js`, `tools/sync-settings.mjs` | The Realm Settings helper every behavior pack copies into its `scripts/settings.js` (packs never import each other); `sync-settings.mjs` copies it, `--check` (part of `npm run check`) fails on a missing or stale copy |
| `tools/zones-shared.js`, `tools/sync-zones.mjs` | The safe zones protocol (providers and consumers of `realm:zones`) that each taking-part pack copies into its `scripts/zones.js`; `sync-zones.mjs` refreshes the copies (`node tools/sync-zones.mjs <folder>` adds a pack), `--check` (part of `npm run check`) fails on a stale copy |
| `tools/admin-catalog.mjs` | Writes `packs/admin_bp/scripts/catalog.js` (every registered `realm:` command, for the Realm Configuration menu) by loading each pack with a stand-in for the Minecraft modules; `--check` (part of `npm run check`) fails when a command changed and it wasn't rerun, or when a command has no button name in `admin_bp/scripts/presets.js` (`NAMES`) or a name or hint is too wide for a button |
| `tools/help-catalog.mjs` | Writes the in-game `/realm:help` text from `docs/PACKS.md`; `--check` (part of `npm run check`) fails if it's stale or a pack doesn't answer `/realm:help` |
| `docs/NEWS.md`, `tools/gen-news.mjs` | Player-facing release notes, newest first. `gen-news.mjs` (run by `npm run bundle`) copies the newest entry into `news_bp`, which pops it up once after an update; `--check` (part of `npm run check`) fails if it's stale |
| `docs/STORY_BIBLE.md`, `tools/check-stories.mjs` | The story bible for Story Questlines (world, cast, places, the data format) and the validator for every story, chapter, objective and favor, which also walks every path through the choices (part of `npm run check`) |
| `tools/test-bds/` | Runs the packs on a real Bedrock Dedicated Server with simulated players and scripted scenarios (`node tools/test-bds/run.mjs --scenario <file>`; downloads BDS on first use). See its README |
| `.claude/skills/bundle-packs/` | The `/bundle-packs` skill |

Script errors show up in the content log (**Settings → Creator → Enable Content Log GUI**).
