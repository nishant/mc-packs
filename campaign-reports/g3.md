# Group 3 verification report (claude/campaign-g3-verified)

Verifier session for group 3 of the fix campaign: performance and the open plan items (W1, O1-O10, O19, F46/F56).
Code under test: `claude/campaign-int23` (cb86c73: release 1 + group 2 + group 3's five workstreams). Before = 7aa0cce
(int23 before group 3). After = this branch.

## Method

- Machine: Claude cloud container, 4 vCPU, 15 GiB, BDS 1.26.52.3, Node 22. Timing runs ran alone, serialized by a
  lock (`flock`); behavior suites never overlapped a timing run, with one exception noted under Risks.
- Perf: `perf-soak.js --profile`, 120 s windows, 10 and 40 players only (owner: 100 players is out of scope; 10 is the
  Realm's maximum and 40 shows scaling). Before and after alternated (base, tree, then tree, base), two runs each.
  Every run passed the perf acceptance check (all players spawned and stayed, full window) unless noted.
- Both trees were measured with this branch's harness (`run.mjs --packs <7aa0cce>/packs`), so only pack code differs.
- Numbers are whole-run ms/tick per pack from the harness profiler (Date.now differences: fine for sums, and per-call
  costs below 0.01 ms are noise).
- Workstream sets (`--only`): WS1 map, hud, saga, elytra, calendar, maps, mobhp, afk; WS2 silly, admin, durability,
  relics, skills; WS3 wander, elite, npc, caravan, moon; WS4 atlas, journal, quests, milestones, titles, nick, afk,

## Decisions

- Measured both trees with this branch's harness (`--packs <7aa0cce>/packs`): only pack code differs between runs.
- Owner (relayed by the main session): 10 and 40 players only, 120 s windows; the 100-player windows (O5, O6) measured
  at 40; no 60-minute soaks (O4 not run).
- WS4: one share per sweep, because measured: +47% / +84% as spread, -11% / -13% with one share. Kept the spreader
  module (one share is a plain sweep of fresh handles) and WS4's other changes.
- map_bp budgets unchanged: a 0.9 ms budget starved single players (map-turn, map-flight); the 1 ms target needs a
  redesign. `budgetLevel` low is 3.5 ms at 40.
- Fade fix: out of budget, a title about to fade is drawn again unchanged (cheap) rather than skipped.
- silly: sweep one player every 4 ticks (not every tick); small servers unchanged.
- side.js: read the kept messages before every own write, in arrival order (the lazy inbox stays, so the traffic win
  stays).
- elite night cost: not changed (per champion flat; near champions step more often by WS3's design).
- npc label loop (0.178 ms a tick in the 40-player stress only): not changed this late (shared module).
- O10 expedition: not split (one step in four at 26 ms against a 25 ms rule).
- Scenario fixes (silly-gear-events, expedition-carts-window, side-boxes, admin-diag, admin-diag-bundle) keep every
  check; each now measures what it says (details above).
- Version bumps: only packs flagged by check-versions (admin 1.6.7 was already master's). Packs whose code changed here
  but were already above master and unreleased in int23 keep their int23 version (the workstreams' convention).
